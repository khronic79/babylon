> Примечание к H-03 (SC-4): продакшн-токен — native USDC Circle на Polygon
> `0x3c499c542cEF5E3811e1192ce70d8cC03d5c3359` (FiatTokenProxy → FiatTokenV2_2).
> По исходникам `centrehq/centre-tokens` (`FiatTokenV2.sol` + `FiatTokenV2_2.sol`
> + `EIP3009.sol`) `receiveWithAuthorization` существует в ДВУХ перегрузках:
> split `(uint8 v, bytes32 r, bytes32 s)` (унаследована из FiatTokenV2) и
> `bytes memory signature` (добавлена в FiatTokenV2_2 для EIP-1271). Интерфейс
> контракта со split-сигнатурой совместим с USDC. Семантика для мока: EIP-712 домен
> `version = "2"`, `RECEIVE_WITH_AUTHORIZATION_TYPEHASH =
> 0xd099cc98ef71107a616c4f0f941f04c322d8e254fe26b3c6668db87aae413de8`, проверка
> `to == msg.sender`, nonce по `authorizer → nonce → bool`, подпись `r||s||v`.
> TODO: подтвердить наличие обеих перегрузок по живому ABI с ноды (публичные RPC
> были недоступны из текущей сети) — проверить с домашнего компьютера.
