# ADR SC-7: Тестовый стек — единый источник ABI и стратегия фикстур

Status: ACCEPTED
Date: 2026-08-22

Связанный план: `docs/plan/SC-7.md`
Связанное исследование: `docs/research/SC-7.md` (§8, §9, §10 ОТВ-7/ОТВ-8)
Источник скоупа кейсов: `test/TEST_PLAN.md`

## Контекст

Эпик SC-7 переписывает тесты под текущий ABI (находка I-03): 88 viem-кейсов (Hardhat +
`@nomicfoundation/hardhat-viem`) + Foundry F-1…F-5. Два решения тестового стека влияют на
архитектуру всех 88 кейсов и на то, как тесты отслеживают изменения контрактов, — поэтому
фиксируются как ADR, а не локальные имплементационные решения.

---

## Развилка 1: единый источник ABI — `artifacts/*.json` vs `parseAbi`

### Решение

Импортировать ABI **из скомпилированных артефактов** `artifacts/contracts/**/*.json`
(как это уже делает `scripts/deploy.ts`), а **не** переобъявлять сигнатуры через `parseAbi`.
Селекторы custom errors при этом — **константы** в `test/helpers/matchers.ts` (сверены с
research §3), а не выводятся из ABI на рантайме.

### Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Итог |
| --- | --- | --- | --- |
| **A. Import из `artifacts/**/*.json`** | Единый источник истины = результат компиляции; нулевой дрейф сигнатур; прецедент `scripts/deploy.ts`; не нужно поддерживать вручную | Требует `resolveJsonModule` + `as const`/касты типов (`strict: true`); ABI «широкий» (все функции/ошибки) | **Принят.** |
| **B. `parseAbi([...])` в хелперах** | Явно, самодокументируемо | Дублирует ABI; дрейфует при правках контрактов; источник ошибок рассинхрона | Отклонён. |

### Обоснование

- **Селекторы ошибок — отдельно, константами.** В ABI артефактов уже есть все ошибки, но у
  прокси и реализации есть одинаковое имя `OnlyAdmin` (один селектор `0x47556579`), а три ошибки
  имеют аргумент-структуру `SettelmentContext`. Ручная сверка первых 4 байт revert-data надёжнее
  и не зависит от ABI-обёртки; `decodeErrorResult` не нужен.
- Свежесть ABI гарантируется порядком запуска: `npx hardhat test` автоматически компилирует
  (`TASK_COMPILE`), поэтому артефакты всегда актуальны.
- Настройка `tsconfig.json` уже содержит `resolveJsonModule: true` — импорт JSON не требует
  изменений конфига.

## Развилка 2: фикстура — `loadFixture` vs собственная снапшот-обёртка

### Решение

Использовать **`loadFixture`** из `@nomicfoundation/hardhat-network-helpers` (уже установлен,
v1.0.12) как единственную точку входа в фикстуру (`test/helpers/fixture.ts`). Собственную
обёртку `takeSnapshot`/`restore` не писать.

### Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Итог |
| --- | --- | --- | --- |
| **A. `loadFixture`** | Стандарт, работает через `evm_snapshot`/`evm_revert` на уровне провайдера; агностичен к ethers/viem; идемпотентен для повторных вызовов | Требует, чтобы фикстура была детерминированной (деплой через `hre.viem`) | **Принят.** |
| **B. Своя `takeSnapshot`/`restore`** | Полный контроль над моментом снапшота | Дублирует существующую функциональность; риск ручных ошибок восстановления; лишний код | Отклонён. |

### Обоснование

- viem wallet-клиенты **stateless** (подписывают и отправляют через publicClient); «сброс» nonce
  аккаунтов снапшотом их не ломает — адреса и nonce восстанавливаются вместе со снапшотом.
- Фикстура детерминирована: деплой через `hre.viem.deployContract` + `getWalletClients()`
  (первые 20 аккаунтов Hardhat), роли закреплены индексами 0–5 (research §7.1, §8).
- Инициализация атомарна через прокси (`data = encodeFunctionData(initialize, [6 аргументов])`
  вторым аргументом конструктора) — «состояние после фикстуры» всегда единообразно.

## Последствия

- **Положительные:** единый стек с будущим `deploy.ts`; ABI никогда не расходится с компиляцией;
  фикстура идемпотентна и переиспользуема во всех 88 кейсах; минимальный собственный код
  (только revert/событийные хелперы поверх viem).
- **Отрицательные:** `test/helpers/*.ts` подхватываются дефолтным сборщиком `npx hardhat test`
  как пустые 0-test suite (безвредно, без side effects на верхнем уровне); ABI из JSON требует
  приведения типов при `strict: true`; селекторы ошибок нужно поддерживать вручную (сверять с
  research §3 при изменении контрактов).

## Проверка

- Тесты импортируют ABI из `artifacts/contracts/**/*.json` (не `parseAbi`); селекторы — константы
  в `matchers.ts`.
- `test/helpers/fixture.ts` экспортирует `useFixture = () => loadFixture(deployFixture)`;
  собственной `takeSnapshot`/`restore`-обёртки нет.
- `npx hardhat compile` → exit 0; `npx hardhat test` → 88 кейсов зелёные без `.env`.
