# ADR SC-1: Устранение «Stack too deep» — структура-контекст `SettelmentContext` вместо `viaIR`

Status: ACCEPTED
Date: 2026-08-20

## Контекст

Находка аудита **C-01 (Critical)**: `contracts/SettelmentsControl.sol` не компилируется
из-за `Stack too deep` (EVM) в функции `paymentClientToNative`. Событие
`PaymentClientToNative` и три custom-ошибки
(`InsufficientClientBalanceForSessionSettelment`,
`NativeAddressIsOutForSessionSettelment`,
`InsufficientContractBalanceForSessionSettelment`) содержат по 11 параметров, из них
3 — `string` (каждая строка = 2 слота стека), итого 14 слотов на параметры + служебные
слоты кодогена. Проект собирается без `viaIR` (`hardhat.config.ts`: optimizer
`runs=1000`, `viaIR` не задан).

## Решение

Перевести событие и три ошибки на единую структуру-контекст `SettelmentContext`
(11 полей), а в `paymentClientToNative` собирать её один раз в memory и использовать
в трёх `revert` и в `emit`. Плюс исправить опечатку: передавать `amountToNative`
(чистую сумму исполнителю) вместо `amount` в 5-е поле.

## Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Итог |
| --- | --- | --- | --- |
| **A. Включить `viaIR: true`** | Минимальная правка конфига; исчезает лимит стека; не меняется ABI. | Меняет весь пайплайн кодогена; влияет на газ и артефакты; требует переверификации/потенциальной ревизии всех байткодов; выходит за рамки «точечного» исправления C-01. | Отклонён. |
| **B. Структура-контекст `SettelmentContext`** | Не меняет конфигурацию сборки и хранилище; сохраняет диагностическую ценность (полный контекст в одном объекте); соответствует намерению «событие и ошибки имеют одинаковый набор полей». | Меняет ABI события/ошибок (11 плоских аргументов → 1 структура); ломает off-chain потребителей до синхронизации. | **Принят.** |
| **C. Разделить ошибки/событие на несколько мелких / убрать часть полей** | Уменьшает стек. | Теряет диагностический контекст; меняет продуктовую семантику событий; более инвазивно, чем нужно. | Отклонён. |

## Обоснование выбора B

- Продукт ещё не в проде, поэтому изменение ABI допустимо.
- Тесты, deploy-скрипт и сабграф уже рассинхронизированы с текущим ABI (research §5),
  их синхронизация — отдельные задачи вне SC-1; точечная правка ABI не усугубляет
  этот факт кардинально.
- Сохраняется инвариант «событие и три ошибки несут один и тот же набор полей» —
  структура-контекст это формализует.
- Не затрагиваются: ручной слот EIP-7201, раскладка `ContractStorage`, формулы комиссии,
  порядок проверок/переводов/списания.

## Последствия

- Положительные: восстановление компиляции без `viaIR`; единый источник истины для
  полей контекста; исправление опечатки `amount` → `amountToNative`.
- Отрицательные: ABI события/ошибок изменён — требует синхронизации off-chain
  потребителей (тесты, deploy-скрипт, сабграф) отдельными задачами.

## Проверка

- Критерий успеха: `rm -rf artifacts cache && npx hardhat compile` → exit 0 без
  `Stack too deep`, при `viaIR` выключенном.
