# ADR SC-3: Конструктор прокси — `bytes memory data` vs явные параметры инициализации

Status: ACCEPTED
Date: 2026-08-20

## Контекст

Находка аудита `docs/audit-reports/2026-08-20.md` — **H-02 (High)**: `initialize`
контракта `SettelmentsControl` защищён только модификатором `initializer`, без
ограничения по `msg.sender`; конструктор прокси деплоит его с пустыми данными, а
`initialize` вызывается отдельной транзакцией. Любой наблюдатель может фронт-ранить
инициализацию и захватить управление.

Выбранный подход (вариант 2 из PRD) — атомарная инициализация через конструктор
прокси. Возникла развилка о том, **какую сигнатуру** придать конструктору прокси.

## Развилка: `bytes memory data` vs явные типизированные параметры

### Решение

Использовать **канонический конструктор OpenZeppelin** с `bytes memory data`:

```solidity
constructor(address implementation, bytes memory data)
    ERC1967Proxy(implementation, data) {
    ERC1967Utils.changeAdmin(msg.sender);
}
```

### Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Итог |
| --- | --- | --- | --- |
| **A. `bytes memory data`** (канонический OZ) | Стандартный проверенный паттерн; прокси остаётся generic и не связан с сигнатурой `initialize`; совместим с экосистемой (OZ upgrades, верификация, deploy-тулинг); не требует правок прокси при будущих изменениях `initialize`. | Не принуждает передавать непустые `data` — «футган» пустой инициализации перекладывается на deploy-процесс. | **Принят.** |
| **B. Явные параметры** `(address, address, address, uint256, address, uint256)` с внутренней кодировкой `abi.encodeCall(initialize, ...)` | Самодокументируется; компилятор гарантирует типы; нельзя случайно передать пустые `data`. | Связывает прокси с конкретной сигнатурой `initialize` — нарушает разделение прокси/имплементации в upgradeable-паттерне; при любом изменении `initialize` (как в SC-2: 5→6 параметров) ломается прокси; расходится с каноном OZ; усложняет верификацию/off-chain тулинг. | Отклонён. |
| **C. Гибрид: `bytes data` + guard на непустоту** | Сохраняет generic-конструктор и закрывает «футган» пустых `data` ревертом. | Добавляет кастомную логику, отсутствующую в каноническом `ERC1967Proxy`; ломает легитимный сценарий деплоя без инициализации (для future upgrades/прочего) — избыточное ужесточение сверх паттерна OZ. | Отклонён. |

### Обоснование

- Вариант A — это ровно тот паттерн, который фиксирует PRD
  (`docs/prd/SC-3.prd.md:37-42`) и подтверждает research §8 (цитата из документации
  `Initializable.sol:33-34` — «initializer should be called as early as possible by
  providing the encoded call as `_data` argument to `ERC1967Proxy`-constructor»).
- Прокси должен оставаться **generic**: его единственная обязанность — установить
  имплементацию, делегировать `initialize` (если `data` заданы) и назначить админа
  прокси. Связывание с сигнатурой `initialize` (вариант B) создало бы хрупкую
  зависимость, которую только что проявил SC-2 (сигнатура `initialize` уже менялась
  5→6 параметров), и потребовало бы правки прокси при каждом изменении логики.
- «Футган» пустых `data` (недостаток варианта A) принимается осознанно: это trade-off
  канонического паттерна, защита от фронт-раннинга обеспечивается **процессом деплоя**
  (deploy-скрипт обязан всегда передавать `abi.encodeCall(initialize, (...))`), а не
  самим контрактом (PRD §«Ограничения», план §5).
- Вариант C отвергнут как избыточное отклонение от канона: реверт на пустые `data`
  не требуется для закрытия H-02 и ограничил бы легитимный generic-деплой.

## Последствия

- **Положительные:** закрытие H-02 (фронт-раннинг инициализации) каноническим
  паттерном; прокси остаётся generic и не требует правок при изменении `initialize`;
  совместимость с OZ-экосистемой и верификацией.
- **Отрицательные:** контракт не принуждает передавать непустые `data` (риск пустой
  инициализации переложен на deploy-процесс); изменение сигнатуры конструктора меняет
  ABI прокси и ломает текущие `test/SettelmentsControlProxy.ts` и `scripts/deploy.ts`
  (синхронизация — вне скоупа SC-3).

## Проверка

- `rm -rf artifacts cache && npx hardhat compile` → exit 0, при `viaIR` выключенном
  (optimizer `runs=1000`, Solidity `0.8.28`).
- Конструктор имеет сигнатуру `(address implementation, bytes memory data)` и
  пробрасывает `data` в `ERC1967Proxy(implementation, data)`, затем
  `ERC1967Utils.changeAdmin(msg.sender)`.
